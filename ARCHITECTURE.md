## APEX source-state rule

A repository's source state, verified receipts, and runtime observations establish what currently exists and what is proven. They do not define the maximum target architecture.

When current implementation is weaker than intended architecture:

```text
CURRENT STATE + INTENDED APEX TARGET + VERIFIED PRIOR GAINS
→ explicit gap
→ strongest coherent development path
→ implementation
→ destructive/adversarial proof
→ runtime proof
→ preserve winner + prior unique gains
→ expand again
```

No generated projection, merge state, CI rule, registry, assistant output, or governance artifact may silently overwrite the intended APEX target.
