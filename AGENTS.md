# APEX Agent Contract

All autonomous and assisted work in this repository operates under [`docs/apex/APEX_CONTRACT.md`](docs/apex/APEX_CONTRACT.md).

## Execution law

- Operator intent controls mission direction, scope, priorities, and architecture target.
- Continue from verified source state; do not reset strong systems without cause.
- Use tools and mutate state when execution is requested.
- Preserve provenance, prior gains, compatibility, observability, and recovery paths.
- Carry material improvements through code, schemas, tests, docs, generated projections, and runtime surfaces where applicable.
- When one path is blocked, pursue the strongest viable alternative rather than converting the blocker into the mission.
- Every material maintenance pass includes a frontier-improvement check.
- No completion claim without executed evidence and readback.

## APEX terminology

APEX is the active project-control vocabulary. Active first-party authority, architecture, runtime, schemas, CLI surfaces, and generated outputs must not reintroduce retired project-control terminology. Historical immutable evidence may preserve exact bytes only for provenance, and active consumers must translate historical semantics into APEX before use.

## Governing objective

`MISSION -> INTELLIGENT ACTION -> VERIFIED OUTCOME -> STRONGER NEXT STATE`
