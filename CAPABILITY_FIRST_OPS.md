# Job-App Helix — Capability-First Operations Guide

**Status:** ACTIVE
**Supersedes:** Governance-heavy workflows in AGENTS.md for this repository
**Authority:** Operator intent — capability over governance

---

## Capability-First Principle

> "Governance serves progress. Progress does not serve governance." — AGENTS.md §1.3

This repository now operates on **executable capability density**, not governance artifact production.

---

## Operational Rules

### 1. Default to Capability Execution
- **Before** creating a manifest, policy, or status file → ask: "Does this execute capability?"
- **Prefer** `python3 -m job_app_helix.<capability>` over writing JSON/YAML
- **Require** hash-bound receipts for every material operation

### 2. Governance Artifacts Are Outputs, Not Inputs
- Manifests, status files, audit reports → **generated by capabilities**, not authored manually
- `monolith.catalog_sync` produces catalog updates
- `portfolio.evidence_ledger` produces evidence ledger
- `evidence.bridge` produces legal spine entries

### 3. Capability Interface Contract
Every capability exposes:
```bash
# CLI (for operators)
python3 -m job_app_helix.<capability> --help

# Library (for agents)
from job_app_helix import <capability_function>

# MCP (for connectors)
# Registered in apex.capabilities.yaml
```

### 4. Verification Gates (Minimal, Enforced)
| Gate | Command | Pass Criteria |
|------|---------|---------------|
| G1 | `python3 -m py_compile src/job_app_helix/*.py` | 0 syntax errors |
| G2 | `pytest tests/ -k "not integration" -q` | Core unit tests pass |
| G3 | `python3 -m job_app_helix.monolith_sync --mode verify` | Sync receipt valid |
| G4 | `python3 -m job_app_helix.capability_federation --domain legal_evidence --requirement ledger` | ≥1 capability found |

**No** CI dashboards, status reports, or planning artifacts required.

### 5. Integration-First Development
- New capability → **immediately** register in `apex.capabilities.yaml`
- New capability → **immediately** test monolith sync + tower resolution
- New capability → **immediately** produce hash-bound receipt
- If it doesn't integrate, it doesn't ship

## Anti-Patterns (Forbidden)

| Anti-Pattern | Replacement |
|--------------|-------------|
| Writing `manifests/*.json` manually | `monolith.catalog_sync` |
| Creating `status/*.md` files | `portfolio.evidence_ledger` output |
| Authoring `policies/*.json` | Capability interface contracts |
| Planning without execution | `automation_engine` + receipt |
| Documentation without code | `apex.capabilities.yaml` + CLI help |

## Escalation Path

1. **Capability gap identified** → Implement capability module in `src/job_app_helix/`
2. **Integration needed** → Add to `apex.capabilities.yaml` with monolith/tower deps
3. **Verification required** → Run G1-G4 gates, produce receipt
4. **Governance demanded** → Generate from capability output, not as prerequisite
