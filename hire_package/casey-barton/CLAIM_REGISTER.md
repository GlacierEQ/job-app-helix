## Tactical rule

Lead with operator or business value, then the architecture, then the exact receipt. Never lead with repository count or technology lists without explaining what changed for a user or team.

Every promotion follows:

```text
mechanism -> test -> execution -> receipt -> bounded claim -> recruiter projection
```

If a stage is missing, preserve the stronger engineering work but keep the external claim at the last verified stage.
