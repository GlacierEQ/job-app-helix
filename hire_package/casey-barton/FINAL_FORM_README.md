## Layer 2 - Senior Engineers, Architects, and Technical Diligence

### Engineering thesis

Probabilistic models become dependable systems only when surrounded by deterministic contracts. The portfolio focuses on that surrounding layer:

```text
human intent
    -> typed request
    -> context and authority resolution
    -> bounded tool plan
    -> permissioned execution
    -> verification
    -> immutable receipt
    -> resumable next state
```

### Core architecture patterns

#### Evidence-bound promotion

Helix uses a monotonic evidence ladder:

```text
INVENTORY -> DOCUMENTATION -> STATIC_ANALYSIS -> BUILD
          -> TEST -> INTEGRATION -> DEPLOYMENT
```

A README cannot prove runtime behavior. A successful build cannot silently become test proof. A zero-test process cannot produce a green test state. A deployment claim requires deployment evidence.

#### Fail-closed execution

- no shell interpolation for discovered command vectors;
- bounded timeouts and output tails;
- explicit authorization before workspace-mutating build actions;
- positive test-count extraction;
- atomic `RUNNING` to terminal-state receipts;
- strongest-adverse-state aggregation;
- path, repository, branch, and input containment;
- least-privilege credentials and nonpersistent checkout.

#### Human-machine artifact twins

Recruiter copy, engineering detail, and machine contracts derive from the same candidate, evidence, relationship, and roadmap records. This prevents a public narrative from drifting away from the proof ledger.
