## Layer 2 - Senior Engineers, Architects, and Technical Diligence

### Engineering thesis

Probabilistic models become dependable systems only when surrounded by deterministic contracts. The portfolio focuses on that surrounding layer:

```text
human intent
    -> typed request
    -> context and authority resolution
    -> bounded tool plan
    -> permissioned execution
    -> verification / evaluation
    -> durable receipt
    -> reconciliation / recovery
    -> resumable next state
```

### Core architecture patterns

#### Evidence-bound promotion

Helix uses a monotonic evidence ladder:

```text
INVENTORY -> DOCUMENTATION -> STATIC_ANALYSIS -> BUILD
          -> TEST -> INTEGRATION -> DEPLOYMENT
```

A README cannot prove runtime behavior. A successful build cannot silently become test proof. A zero-test process cannot produce a green test state. A deployment claim requires deployment evidence.

#### Longitudinal agent evaluation

Make-It-Heavy separates worker structural quality, legacy heuristic benefit, causal marginal system value, and outcome leverage. Matched experiments can freeze topology, isolate one changed template axis, preserve comparison lineage, and record ablation results without relabeling unmeasured causal fields as success.

The current external worker baseline is real and reviewable, but the causal claim ceiling remains intentionally lower: matched rerun and ablation evidence are still required before claiming worker improvement.

#### Fail-closed execution and recovery

- bounded and typed execution contracts;
- durable idempotency and one-shot transport-entry fencing;
- exact request / permit / envelope identity binding;
- explicit `recovery_required` or unresolved states after ambiguous provider outcomes;
- no blind replay after uncertain execution;
- provider-aware read-after-write observation where the provider exposes suitable version semantics;
- strongest-adverse-state aggregation;
- path, repository, branch, and input containment.

#### Capability security

- declared capabilities and exact tool allowlists;
- durable lease state before remote execution;
- exact registry / plan hash binding;
- short-lived attenuated tokens for the exact execution surface;
- master credential separation from tool execution;
- explicit write / destructive confirmation gates;
- conservative treatment of incomplete MCP annotations;
- hash-only persisted error evidence where raw content could leak secrets.

#### Human-machine artifact twins

Recruiter copy, engineering detail, and machine contracts derive from the same candidate, evidence, relationship, and roadmap records. This prevents a public narrative from drifting away from the proof ledger.
