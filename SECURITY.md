# Security Policy

## Supported version

Security fixes are applied to the latest `main` branch.

## Reporting

Do not open a public issue for a suspected secret, personal-data exposure, or exploitable vulnerability. Report it privately to the repository owner through the contact method listed on the GitHub profile.

Include the affected path, commit, reproduction steps, impact, and any safe remediation you tested.

## Repository boundary

This public repository must not contain credentials, private evidence, generated IDE memory, personal machine paths, or legal and family-case material. CI performs pattern and boundary checks, but automated scanning does not replace manual review.
