## Active state law

Principal states:

`DISCOVERED → IDENTITY_RESOLVED → PURPOSE_RECONSTRUCTED → CAPABILITY_MAPPED → RESTORATION_COMPOSED → IMPLEMENTED → TESTED → ADVERSARIAL_VERIFIED → OPERABLE → PROOF_REPRODUCED → PROMOTED → CANONICAL → EVOLVING`

`CANONICAL` is an exact-source anchor for a named capability only. It does not erase siblings or acquire authority over OPERATOR intent.

Active facets:

`BLOCKED`, `EXPERIMENT`, `REFERENCE`, `DONOR`, `RECOVERY_REQUIRED`, `COMPOSITION_REQUIRED`.

Historical contraction labels remain parseable only so old receipts can be understood. They cannot be emitted by active execution.

## Gatling / tsunami / unified memory

- **Gatling:** many independent capability lanes in parallel.
- **Tsunami:** meaningful implementation/proof checkpoints emit receipts into the memory/event bus.
- **Unified memory:** each worker receives purpose, lineage, donors, prior gains, failures, tests, and current frontier instead of starting blank.
- **Composition:** sibling specialists exchange capabilities through explicit interfaces rather than being collapsed merely because they overlap.

Orchestration stays efficient; implementation workers go deep.

## Retirement is outside this machine

This compiler cannot mark a repository or branch ready for deletion, archive, merge-away, or close-as-duplicate. Similarity, patch equivalence, proof weakness, age, and successor existence are insufficient.

A destructive lifecycle change requires separate OPERATOR authorization after full capability and lineage reconstruction plus verified preservation of useful gains.

## P0

Current high-value proof surfaces should be treated as donors and integration anchors for the broader estate, not as excuses to reduce the long tail. Every relevant repository remains eligible for recovery, composition, implementation, and elevation.
